# 交互状态与可访问性规则

对应问题：按钮没有悬停反馈、没有加载态、列表为空时一片空白、出错没有提示、只用 placeholder 当标签、键盘无法操作、对比度不足。
> 交互行为（异步反馈、防重复、浮层键盘行为、悬停/触屏）的完整规则见 interaction.md；本文件侧重每个元素的状态和可访问性底线。


## 1. 每个交互元素的状态矩阵

| 状态 | 要求 |
|---|---|
| default | 来自组件 variant |
| hover | 有可感知变化（背景/边框/文字色），不要只改 cursor |
| focus-visible | 明显的焦点环（使用令牌颜色），不要 `outline: none` 后什么都不给 |
| active | 按下反馈 |
| disabled | 视觉弱化 + `disabled` 属性 + 不响应点击；不要只改透明度而仍然可点 |
| loading | 按钮保持原宽度（防止抖动），显示 spinner，并禁止重复提交 |
| selected/checked | 不能只靠颜色区分，配合图标、粗细或背景 |

使用项目组件时这些状态一般已内置；自定义交互元素（可点击卡片、列表项）必须自己补齐。

## 2. 数据视图的四态

每个依赖异步数据的区域（表格、列表、卡片墙、图表、详情）都要处理：

1. **加载中**：骨架屏或占位，占位尺寸接近真实内容，避免加载完成后布局跳动。
2. **空状态**：说明为什么空 + 下一步操作（"暂无订单，调整筛选条件" / "新建"）。筛选无结果和本来就没数据要区分文案。
3. **错误**：说明出错 + 重试按钮；不要静默失败或只在控制台打印。
4. **正常**：包括数据很多（分页/虚拟滚动）和单条数据很长（截断规则见 layout.md）。

写代码时在规划阶段就列出这四态，而不是等用户发现白屏。

## 3. 表单

- 每个字段有可见 label；placeholder 只做示例，不做说明。
- 必填标识统一；错误信息显示在字段下方，靠近出错位置，而不是只在顶部弹一个提示。
- 提交按钮在提交中禁用并显示 loading。
- 输入类型正确（`type="email"`、`inputmode="numeric"`），移动端弹出合适的键盘。

## 4. 可访问性底线

- 图片有 `alt`（装饰图 `alt=""`）。
- 仅有图标的按钮有 `aria-label`。
- 文字对比度至少 4.5:1（大字 3:1），次级文字色也要满足。
- 可点击的非按钮元素（div 卡片）要么换成 button/a，要么补 `role`、`tabIndex=0` 和键盘事件。
- 状态不只用颜色表达（成功/失败配图标或文字）。
- 弹窗焦点管理见 layering.md。
