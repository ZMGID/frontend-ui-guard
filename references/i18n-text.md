# 长文本与多语言规则

对应问题：中文排得好好的，换成葡萄牙语/英语/西班牙语后按钮换行、表头撑破、Tab 挤爆、标签截断；金额和日期格式不对导致列不齐。

## 1. 文本长度预算

相对中文，西方语言的同一文案通常长得多（葡萄牙语、西班牙语、德语尤其明显，常见 2~3 倍字符数、1.3~1.8 倍显示宽度）。因此：

- 设计布局时按目标语言中最长的文案估算，而不是按中文或示例文案。
- 按钮、Tab、表头、标签、徽标、菜单项这类"短文本容器"必须明确溢出策略（见 layout.md 第 4 节），不能假设文字短。
- 不给文本容器写死宽度；用 `min-width` + 内容自适应，必要时 `max-width` + 截断 + tooltip。
- 按钮组、Tab 栏允许 `flex-wrap` 或折叠进"更多"。
- 表头文字可换行（两行以内），列宽不要按中文表头设定。
- 用 `layout_check.cjs --stress` 模拟长文本做压力测试，这是发现这类问题最便宜的办法。

## 2. 数字、货币、日期

- 金额、日期、数量不要手动拼字符串，使用 `Intl.NumberFormat` / `Intl.DateTimeFormat`（或项目已有的格式化工具）。例如巴西：`new Intl.NumberFormat('pt-BR', { style: 'currency', currency: 'BRL' })` 输出 `R$ 1.234,56`——千分位是点、小数是逗号。
- 数字列 `text-align: right` + `font-variant-numeric: tabular-nums`，保证不同行的数字位对齐。
- 货币符号和金额之间不要被换行拆开（格式化结果中通常已含不换行空格，不要替换掉）。

## 3. 文案与字体

- 所有用户可见文案走项目的 i18n 方案（如果有），不在组件里硬编码。
- 确认字体覆盖目标语言的特殊字符（葡语的 ã、ç、õ、é 等），缺字形会回退到系统字体导致宽度和风格不一致。
- 大写转换（`text-transform: uppercase`）会让葡语等语言变得更长，谨慎使用。
