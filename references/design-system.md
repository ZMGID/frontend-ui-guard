# 设计系统与组件复用规则

对应问题：全局按钮、滚动条、输入框等组件没用上，直接用原生标签或又写了一个；颜色、间距、字号各处不一致；排版没有章法。

## 1. 复用协议（每次写 UI 元素前执行）

1. **查清单**：在 `.ui-guard/inventory.md` 或项目 `ui-rules.md` 里查找对应组件。
2. **查不到就搜**：按名字和用途 grep，例如按钮搜 `Button|Btn|btn`，滚动条搜 `scrollbar|Scroll`，弹窗搜 `Modal|Dialog|Drawer`。同时看全局 CSS 里定义的类（`.btn-primary`、`.app-scrollbar`、`.card`）。
3. **找到了就用**，用它的 props/variant/size 表达需求，不在外面再包一层样式覆盖它。
4. **现有组件差一点**：优先加 variant 或 size，并且只在 variant 的层面扩展（例如 `variant="danger-ghost"`），而不是加布尔 prop（`isRed`、`isSmall`、`noPadding`）。每加一个布尔开关，组件状态组合翻倍，视觉 bug 面也翻倍。
5. **确实没有**：新建组件放在项目组件目录，命名和已有组件风格一致，并在汇报里说明"新增了 X，因为现有的 Y 不满足 Z"。
6. **不引用** `legacy`、`deprecated`、`old`、`_bak` 目录下的组件，即使它就在旁边。

为什么这很重要：模型写代码时会模仿附近文件的写法，如果附近是旧代码或原生写法，就会被带偏。所以要主动查清单，而不是看邻居。

## 2. 原生标签的边界

在业务代码（页面、业务组件）中，以下元素一律使用项目组件，不直接写原生标签加样式：

| 原生 | 应使用 |
|---|---|
| `<button>` | Button / IconButton |
| `<input>` `<textarea>` | Input / Textarea / 表单组件 |
| `<select>` | Select |
| `<dialog>` 或自写遮罩 | Modal / Drawer |
| `<table>` 手写样式 | Table 组件 |
| `overflow:auto` 的 div | 加全局滚动条类 或 ScrollArea 组件 |
| 自写 tooltip/下拉 | Tooltip / Dropdown / Popover |

例外：组件库本身的实现文件（ui/primitives 目录）可以用原生标签。

## 3. 设计令牌

- **颜色**：只用语义令牌（`--color-primary`、`--color-text-secondary`、`--color-border`、`--color-danger`，或 Tailwind 主题中的对应名字）。禁止 hex/rgb/hsl 字面量，禁止 Tailwind 默认色板的随手使用（例如项目主色是品牌蓝时写 `bg-blue-600`）。
- **间距**：只用刻度值（常见 4px 基准：0, 2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64）。禁止 `p-[13px]`、`margin: 7px`。
- **圆角、阴影**：只用令牌。同一类元素（所有卡片、所有输入框）圆角一致。
- **字号**：限定 5~6 档（例如 12/14/16/20/24/32），相邻档位之间要有明显差距。同一层级的文字用同一档；不要出现 14、15、16 混用。
- **字重**：正文 400，强调 500/600，标题 600/700。不要到处 700。

如果项目没有令牌：先按现有代码中最常用的值归纳出一套（scan_project.py 的输出里有统计），和用户确认后再统一。

## 4. 排版章法（让页面"有布局"）

一个后台/运营类页面的标准骨架：
```
页面容器（max-width 或满宽，统一左右内边距）
├─ 页头：标题 + 描述（左） | 主操作按钮（右）
├─ 筛选区：一行 flex-wrap，控件同尺寸，右侧"查询/重置"
├─ 内容区：卡片/表格，与筛选区间距固定（如 16）
└─ 分页/底部操作：右对齐
```

规则：
- **统一的页面边距和区块间距**：整站只用一两个值（例如区块间 24、区块内 16）。
- **对齐线**：同一页面内所有区块左边缘对齐，不要一个区块有 padding 一个没有。
- **信息层级**：每个区块只有一个最强视觉元素（标题或关键数字）；次要信息用次级文字色和小一档字号。
- **主操作唯一**：一个区域只有一个主按钮（primary），其余用次级或文字按钮。
- **表单**：标签在上或左对齐统一；两列表单用 grid；字段宽度按内容预期长度而不是全部拉满。
- **密度一致**：同一页面行高、控件尺寸、表格行高使用同一档。

## 5. 修复配方

| 症状 | 改法 |
|---|---|
| 又写了一个按钮组件 | 删除，替换为现有 Button 的对应 variant；缺 variant 就在原组件加 |
| 原生 `<button className="...">` | 换 `<Button>`，把样式意图映射为 variant/size |
| 出现浏览器默认滚动条 | 滚动容器加全局滚动条类或改用 ScrollArea |
| 颜色有三四种相近的蓝 | 全部替换为 `--color-primary` 系列令牌 |
| 间距看着乱 | 改用父级 gap + 刻度值；删除零散 margin |
| 字号层级不清 | 归并到 5~6 档，拉开相邻层级差距 |
