# 交互设计规则

对应问题：点了没反应、重复提交、失败无提示、弹窗关不掉/Tab 跑到背后/背景还能滚、下拉点外面不收起、悬停才出现的操作在手机上找不到、刷新后筛选全丢、快速操作界面闪回、搜索结果乱序、删除没有确认、整行看起来能点但只有文字能点。

## 1. 每个动作都是一个状态机

写任何会触发请求或耗时的操作前，先写出它的状态：

```
idle → pending → success | error
             ↘（再次点击：忽略，不能重复发出）
error → 可重试（按钮恢复可用，错误信息可见）
```

规划阶段就要回答：pending 时按钮长什么样？成功后界面怎么变（列表刷新、弹窗关闭、toast）？失败时错误显示在哪里、能不能重试？AI 最常见的写法是只写 happy path：`onClick={async () => { await save(); close(); }}`——没有 pending、没有 catch、失败时弹窗照样关闭或什么都不发生。

## 2. 反馈

- **即时反馈 < 100ms**：点击后按钮必须立刻有变化（按下态、loading），不能等请求回来。
- **加载按钮**：显示 spinner 并**保留原文字**（或"保存中…"），按钮宽度不变。
- **加载指示防闪烁**：请求很快时不要闪一下 spinner。显示前延迟约 150–300ms，一旦显示至少保持 300–500ms。
- **结果反馈**：成功有确认（toast、行内对勾、数据更新可见）；失败有说明 + 下一步（重试、修改哪里）。错误信息写"怎么办"，不是只写"失败"。
- **toast** 不遮挡主要操作区域，不超过 3 条堆叠，错误类 toast 不自动消失或停留足够久；用 `aria-live="polite"`。
- **空结果 vs 加载中 vs 出错** 三种状态必须能区分，不能都是一片空白。
- **不留死路**：每个页面/状态都有下一步（空状态给入口、错误给重试、404 给返回）。

## 3. 异步：防重复、竞态、乐观更新

- **防重复提交**：请求开始后禁用提交按钮（或忽略后续点击）直到结束；表单 Enter 键同样受控。有条件的话带幂等 key。不要在请求开始前就预先禁用提交按钮——应允许提交不完整的表单以显示校验错误。
- **竞态**：搜索框、筛选、分页、Tab 切换会连续发请求，旧请求可能晚到并覆盖新结果。必须取消旧请求（AbortController / 查询库的自动取消）或丢弃过期响应（比较请求序号）。
- **防抖**：输入即搜索用 250–400ms 防抖；按钮点击不用防抖（用 pending 状态）。
- **组件卸载**：离开页面时取消进行中的请求和定时器，避免回来后状态错乱。
- **乐观更新必须能回滚**：先改界面再发请求时，失败要恢复原状并提示；进行中的旧查询要取消，防止旧数据把乐观状态"闪回"。搜索/筛选不要做乐观更新。
- **轮询**：页面不可见时暂停（`visibilitychange`），语言切换等无关变化不应重置轮询。
- 优先使用项目已有的数据层（React Query / SWR / 自研 hooks），它们通常已经解决了取消、去重、重试；不要在组件里裸写 `useEffect + fetch`。

## 4. 浮层行为

**弹窗 / 抽屉**——优先用项目的 Modal/Drawer 组件，它们应当统一提供以下行为；自己写的必须全部补齐：
- `role="dialog"`（确认类 `alertdialog`）+ `aria-modal="true"` + 可访问名称（`aria-labelledby` 指向标题）。
- 打开时焦点移入弹窗（第一个输入框或关闭按钮）；Tab/Shift+Tab 限制在弹窗内；背景 `inert`。
- Esc 关闭（有未保存内容时先确认）；点击遮罩关闭（表单类弹窗可不关，避免误触丢数据）。
- 关闭后焦点回到触发按钮。
- 打开时锁定背景滚动，弹窗内部滚动用 `overscroll-behavior: contain`，防止滚到底带动背景。
- 弹窗叠弹窗时，Esc 和点外面只关闭最上层。
- 高度超出视口时内部滚动，头部标题和底部按钮固定（见 layout.md §5）。

**下拉 / Popover / 菜单**：
- 点击外部、Esc、选择后关闭；同一时间只打开一个。
- 触发器有 `aria-expanded`；菜单支持方向键。
- 靠近视口边缘自动翻转（组件库自带；手写的用 floating-ui）。
- 从触发器方向展开（见 motion.md）。

**Tooltip**：
- 只放补充信息，不放必须看到的内容和可点击内容（触屏上看不到）。
- 首次显示延迟约 300–500ms，同组内移动到相邻元素时立即显示。
- 禁用按钮上的 tooltip 要包一层元素，否则事件不触发。
- 能用行内说明就不用 tooltip。

## 5. 表单交互

- 校验时机：失焦时校验单个字段，提交时校验全部；不要在用户刚开始输入时就标红。
- 提交失败：滚动并聚焦到第一个错误字段；错误信息在字段旁边。
- 不要阻止输入（只允许数字时也让用户输入，然后提示），不要禁止粘贴。
- 单输入框 Enter 提交；textarea 中 Enter 换行、Ctrl/⌘+Enter 提交。
- 有未保存修改时，离开页面或关闭弹窗前提示。
- 正确的 `type` / `inputmode` / `autocomplete`；输入值去掉首尾空格再校验。
- 点击 label 能聚焦对应控件；复选框和文字是一个整体点击区域。

## 6. 点击目标与语义

- **导航用 `<a href>`**（支持新标签页打开、右键、中键），操作用 `<button>`。不要用 `div onClick` 做导航或按钮。
- **所见即可点**：看起来可点的整块区域（卡片、列表行）都要可点，不能只有文字能点；反过来，不可点的东西不要有 hover 手型和变色。
- **不要嵌套可交互元素**（按钮里套链接、可点击卡片里又有按钮但没有阻止冒泡）。整行可点又有行内按钮时，行内按钮 `stopPropagation`，或改为"标题是链接 + 其余是按钮"的结构。
- 可点击区域不小于 24×24px，移动端 44×44px；小图标按钮用 padding 扩大热区。
- 纯图标按钮有 `aria-label`。
- `href="#"`、`javascript:void(0)` 不要出现。

## 7. 悬停、触屏与键盘

- **悬停才显示的操作**（表格行 hover 才出现编辑/删除）在触屏和键盘下不可见。至少同时在 `:focus-within` 时显示，移动端默认显示或放进"更多"菜单。
- 悬停效果用 `@media (hover: hover)` 包裹，避免触屏上点一下后"粘住"。
- 悬停位移（`translateY(-4px)`）不要大到让指针离开元素而来回闪烁；位移放在内层，外层保持热区不动。
- 所有流程键盘可完成；焦点可见（`:focus-visible` 焦点环）；焦点不被吸顶头部遮住（`scroll-margin-top` / `scroll-padding-top`）。
- 不设置正数 `tabindex`；Tab 顺序符合视觉顺序。
- 不禁用浏览器缩放（`user-scalable=no`）。
- 控件设置 `touch-action: manipulation` 避免双击缩放延迟。

## 8. 状态持久化与导航

- 筛选条件、Tab、分页、排序、搜索词、展开的面板：放进 URL 查询参数，刷新、分享、前进后退都能恢复。
- 从列表进入详情再返回，滚动位置和筛选条件保持。
- 修改筛选条件时页码回到第 1 页；删除当前页最后一条时回到上一页。
- 页面 `<title>` 随当前内容变化。

## 9. 危险操作

- 删除、清空、批量操作：二次确认（说明影响范围："将删除 12 个商品"），或提供撤销窗口。
- 确认弹窗使用项目的 ConfirmDialog，不用 `window.confirm` / `alert`。
- 危险按钮用 danger 样式，且不是默认焦点；确认按钮文字写明动作（"删除 12 个商品"而不是"确定"）。
- 批量操作显示进度和部分失败的结果。

## 10. 修复配方

| 症状 | 根因 | 改法 |
|---|---|---|
| 连点两次产生两条数据 | 没有 pending 状态 | 请求开始即禁用 + loading；表单 Enter 也走同一逻辑；后端幂等 |
| 点了没反应，过一会儿突然变化 | 没有即时反馈 | 按下立即进入 pending 态并显示 |
| 失败什么都没发生 / 弹窗照样关了 | 只写了 happy path | try/catch，失败保留弹窗、显示错误、恢复按钮 |
| 搜索结果对不上输入 | 请求竞态 | 取消旧请求或丢弃过期响应；防抖 |
| 勾选后闪回再变回来 | 乐观更新被旧查询覆盖 | 变更开始时取消相关查询；失败回滚 |
| 弹窗 Esc 关不掉、Tab 跑到背后、背景滚动 | 手写弹窗 | 换成项目 Modal 组件（或补齐 §4 全部行为） |
| 下拉点外面不关 | 手写下拉 | 用组件库 Dropdown/Popover |
| 手机上找不到编辑按钮 | 仅 hover 显示 | 加 focus-within 显示；移动端常显或收进"更多" |
| 刷新后筛选丢失 | 状态只在 useState | 同步到 URL |
| 整行只有文字能点 | 点击事件绑在内层 | 整块元素成为链接/按钮，或扩大热区 |
